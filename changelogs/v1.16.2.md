# v1.16.2 — stop world swaps writing game state back into config.yml

Startup already migrates mutable game state out of `config.yml` into `state.yml`. But
`WorldManager.applyWorldConfig()` copied **every** key from a world template into the main
config and called `saveConfig()`, and all three shipped templates carry six of those state
keys — `first_beacon_converted`, `humans_own_all_beacons`, `vampires_own_all_beacons`,
`one_human_left`, `fourth_book_has_spawned`, `fourth_book_spawn_enabled`.

So every world swap undid the migration, put the state straight back into `config.yml`, and
stripped the file's comments on the way out.

The key list is now a single shared constant, `VampireSMPPlugin.STATE_KEYS`, used both by
the startup migration and by `applyWorldConfig`, which routes those keys to `state.yml`
instead of the main config. The swap log line now reports how many were routed.

Verified against all three templates: 6 state keys each, none left writing to `config.yml`.

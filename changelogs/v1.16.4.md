# v1.16.4 — fix five bugs found by the audit

Each was confirmed before the fix and re-verified after, by driving the real shipped
classes rather than a re-implementation.

## P1-1 / P3-4 — Fading bypass perks (FadeManager)
`perksGranted` was assigned only inside `if (!player.getAllowFlight())`, while
`setExternalNoclip(true)` and the chat message sat outside it. A bypass player who already
had flight never recorded the grant, so the block re-entered every tick and both revoke
paths — gated on that same flag — could never run.

Split into two flags: `perksGranted` (set unconditionally, so the grant happens once) and
`grantedFlight` (records whether *we* switched flight on, so we only take back what we gave).

    before:  flight@start=true  -> msgs=150  perks never revoked
    after:   flight@start=false -> msgs=1  revoked, flight taken back
             flight@start=true  -> msgs=1  revoked, flight left alone

At TICK_INTERVAL=2 that was 10 messages/second for a 300s fade, then noclip stuck until relog.

## P2-1 — tome cooldowns survived a new session
Session resets called `VampireAbilityManager.clearAllCooldownsForNewSession()`, which only
clears that manager's own maps. `TomeAbility` keeps a separate static map, so every tome
cooldown crossed the boundary — with Fading at 300s a fresh session could open with someone
locked out over the previous one.

Added `TomeAbility.clearAllForNewSession()` (clears the map and cancels pending "ready"
tasks) and wired it into all three session-reset sites. Fae bargains are deliberately left
alone: they are earned, not per-session.

    seeded 2 players -> after clearAllForNewSession(): 0 remain; 3/3 call sites wired

## P2-3 — a misconfigured cap silently disabled permadeath
The death counter is clamped to `combat.human-death-score-cap`; permadeath fires at
`combat.vampire-kill-permadeath-threshold`. With the threshold above the cap the counter can
never reach it and the 5-death rule quietly never triggers. config.yml documented the rule;
nothing enforced it.

Added `ConfigManager.validateGameplayInvariants()`, surfaced to admins on join beside the
existing location warnings.

    cap=5  threshold=5  -> silent        cap=5  threshold=10 -> warns
    cap=10 threshold=5  -> silent        cap=3  threshold=5  -> warns

## P3-7 — double message when crafting out of session
`VampireCraftBlocker` cancelled the event and messaged, then fell through to the
blocked-weapon check and messaged again. Added the missing `return`.

## P3-9 — thrall bond files could be written by two threads
`flushDirtyBonds` guards itself with `savingNow` and hands file I/O to an async task, but
neither `saveOneBondSync` nor `saveAllBondsSync` consulted it. A player quitting — or the
server shutting down — mid-flush could put two threads on the same file, and
`YamlConfiguration.save` truncates before writing.

Both sync paths now call `awaitAsyncWrites()` first, bounded to 2s so a wedged write cannot
hang the main thread or block shutdown.

This one is a race: the missing guard was definitive, the corruption it allowed was not
reproducible on demand, and I am not claiming to have observed it.

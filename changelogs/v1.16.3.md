# v1.16.3 — /pow tome scrying can finally take a player

`/pow tome scrying <player>` had nowhere to put the player name.

`/pow` is served by Brigadier, and its tree ended at the ability argument:

```
literal("tome")
  .then(literal("list"))
  .then(argument("ability").suggests(tomeAbilities).executes(...))   <- nothing after this
```

So there was no node for a second argument: no tab-completion, and a trailing name was
rejected as bad syntax. Everything behind it already worked — `TomeAbilityCommand` forwards
trailing arguments to the ability, and even has a Bukkit tab-completer that suggests players
for scrying (line 103). That completer simply never runs, because Brigadier serves `/pow`.

This is the two-file trap this command tree keeps setting: handling a subcommand in
`PowCommand` is not enough, `BrigadierCommands` has to make it reachable.

## Fixed
Added a `target` argument under `ability`, with suggestions that depend on the tome:

- **Scrying** suggests online players, excluding yourself — pointing the arrow at your own
  position is not useful.
- **Fading** suggests opacity steps (0, 25, 50, 75, 100), since that is its optional argument.
- Anything else suggests nothing, rather than offering a misleading player list.

Both nodes stay executable, so `/pow tome scrying` on its own still fails with its own message
instead of a syntax error.

## Verified
Built the real `/pow` tree and inspected it: `tome -> ability -> target`, all executable.

# v1.15.17 — MC 1.21.10 — 2026-08-20

## Fixed
- **Reviving a ghost now permanently corrupts the beacon instead of resetting it to neutral.**
  The ritual called `setBeaconNeutral`, which handed the site back as contestable ground — so a
  single desecrated beacon could be recycled for revival after revival. It now ends as
  `PERMANENTLY_DESECRATED` (Corrupted), matching the vampire cure.

## Changed
- New `BeaconManager.setBeaconPermanentlyDesecrated(name, reason)` — the single path for a ritual
  that consumes a beacon outright. It cancels any pending neutral broadcast, clears the conversion
  cooldown, updates the display, saves, refreshes majority bonuses, broadcasts the change, and
  re-checks complete control, Humans' Final Stand and Eternal Night.
- **The vampire cure now uses that same method**, so the two rituals cannot drift apart. This
  removed 25 lines of duplicated Eternal Night logic from `VampireCureCommand`.
- Eternal Night triggering moved into `BeaconManager.checkAndTriggerEternalNight()`, the symmetric
  counterpart to the `checkAndDisableEternalNight()` it already owned.

## Notes
- The revival now also records *what* corrupted the beacon ("Revival ritual by <player>"), so
  `/pow admin beacon list` shows the cause.
- `BeaconConversionListener` keeps its own Eternal Night trigger, which applies **5 seconds** of
  darkness to survival players only, where the ritual path applies **infinite** darkness to all
  humans. The infinite form is the coherent one — `checkAndDisableEternalNight` is what removes
  it — but conversion behaviour was left untouched here rather than changing gameplay as a side
  effect of a bug fix. Worth unifying deliberately later.

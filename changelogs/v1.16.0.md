# v1.16.0 — MC 1.21.10 — 2026-08-20

## Added
- **CustomPlayerModels is now built into the plugin** (MIT, tom5454 — see `LICENSE-CPM`).
  The server half of CPM 0.6.27a ships inside WerePires rather than as a separate plugin, so the
  source is ours to modify. 593 files: CPM's shared core plus its Paper module.
- `/cpm` registers through Paper's Brigadier lifecycle as before; `cpm.*` / `cpm.command`
  permissions are declared in WerePires' own `plugin.yml`.

## Changed
- `CPMPaperPlugin` no longer extends `JavaPlugin` — a jar can only declare one main class, and
  WerePires owns it. It is driven as a component from `VampireSMPPlugin.onEnable/onDisable`, with
  delegating accessors (`getDataFolder`, `getLogger`, `getServer`, `getDescription`,
  `getLifecycleManager`) standing in for the base class. **The body of `onEnable()` is unchanged
  from upstream**, so pulling a newer CPM is still close to a straight copy.
- CPM writes its `cpm.json` / `cpm.lang` into a `cpm/` subfolder of the WerePires data folder
  rather than the root.
- `Network` takes a `JavaPlugin` instead of `CPMPaperPlugin`; every use of it was already
  Bukkit `Plugin` behaviour.
- CPM start-up is wrapped in a `try/catch` — if it fails, it is logged and WerePires continues.

## Fixed
- **Maven resource filtering is now off.** It was corrupting binary assets: CPM ships `.png` and
  `.xcf` files and the build died with `MalformedInputException`. Nothing under `resources/` uses
  `${...}` properties — the version in `plugin.yml` is bumped directly — so filtering was pure
  risk for no benefit. The pom already carried a comment warning that filtering corrupts binaries;
  this removes the hazard rather than extending an exclusion list.

## Notes
- Jar grew from ~1.4 MB to **4.1 MB** (1099 `com.tom` classes, 135 CPM assets).
- Two new `provided` dependencies — `netty-all` and `brigadier` — both supplied by Paper at
  runtime, matching CPM's own `compileOnly` scopes.
- **The Fabric/client half is not in this release.** CPM's Fabric module uses Mojang mappings
  while the compat mod uses Yarn, and the two cannot share a source set; that half is being done
  as a separate Gradle module combined via Jar-in-Jar.
- Not runtime-tested: this compiles and packages correctly, but CPM has not been started on a
  live server yet.
